# 制作约定

## 先后顺序

1. 核对主题与固定上游提交，建立范围、来源、手算样例及反例。
2. 写课程设计和计划；验证纯 JS 引擎和独立 Python 参考。
3. 建完整双语网页、实验、练习、资料页和 Worker Python。
4. 使用引擎导出数据，写双语旁白与语义对齐表；先看实帧和真实样片，再合成全片。
5. 验收网页和影片，依据观察修正试点和 skill；冻结迁移版。
6. 后续课消费迁移版，完整制作一次；验收、修复实际错误、发布。

## 建议文件组织

`site/` 包含可直接发布的主页、assets、reading、python、downloads、media 和按需运行时；`src/` 或 `site/assets/` 保存无 DOM 引擎；`video/` 保存双语分镜、导出数据、语义对齐、冻结音频、时间轴和许可字体；`scripts/` 保存可复现制作与验收命令；`tests/` 保存有教学意义的数学和行为检查；`docs/qa/` 记录实际结果。

`PROGRESS.md` 必须有当前阶段、下一步、已验收证据、真实限制及线上提交。`docs/skill-iteration.md` 对试点记录 skill 修改的实际原因。后续课记消费版本与 SHA256。不把计划写成验收结果。

## 范围与自主推进

单课制作以用户链接到的 module 为边界。不要把整站 playbook 的章数、片数、字数、PPTX 配额当作新任务额外要求。优先完成教学闭环。已经明确要求发布且目标仓库清楚时，例行设计、依赖、实现、测试、普通提交、推送与 Pages 配置属于执行范围；不得因此重新等待用户批准设计。

## 可复用基线

在当前工作区，`eda-placement-lesson3/` 是最近完成的参考实现：语言与影片联动、站内阅读页、本地 Pyodide、Worker 停止/超时、双语字幕和媒体验证都可参考。复制通用组件时检查许可并去掉线长模型、课名、数值、缓存、学习进度键和过期部署声明。

`Partitioning_Module_Coordinator/` 提供动画配色与更早制作经验，只读参考，除用户额外授权不得改变其内容或定时任务。
